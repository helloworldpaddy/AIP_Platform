ADK Web — AML investigation agents (dev / debug only)
======================================================

The AML stage agents now live in the backend package as a single source of
truth shared with the FastAPI orchestrator:

  backend/aml/agents/stages/
    initial_assessment/agent.py      -> root_agent
    transaction_enrichment/agent.py  -> root_agent
    due_diligence/agent.py           -> root_agent
    case_analysis/agent.py           -> root_agent
    rag_agent/agent.py               -> root_agent (re-export of agents/rag_agent)

Prerequisites
-------------
- Python env with `google-adk` (same as backend `requirements.txt`).
- `GOOGLE_API_KEY` (or Vertex env vars) for Gemini.

Run the Web UI
--------------
From the repository root, point `adk web` at the stages directory:

  export GOOGLE_API_KEY=...        # or load from docker/.env
  adk web backend/aml/agents/stages --port 8000

Open http://localhost:8000 and pick an agent in the top-left:

  initial_assessment
  transaction_enrichment
  due_diligence
  case_analysis
  rag_agent

Each folder's `agent.py` defines `root_agent` for that workflow stage.

Behaviour vs production
-----------------------
These are the SAME agent definitions used by the FastAPI orchestrator. The
tools (`backend/aml/agents/tools/context_aware.py`) are context-aware: when the
orchestrator binds a DB context they perform real reads/writes; in standalone
`adk web` (no context / unconfigured providers) they return stub results
(`adk_web_stub` / `adk_web_note`) so prompts and JSON output can be exercised
without a database.

Hybrid ADK web (all four stages — case number driven)
----------------------------------------------------
All workflow stage agents include ADK callbacks that wire real Postgres +
providers when you include a case number in the user message:

  export GOOGLE_API_KEY=...
  export POSTGRES_HOST=localhost POSTGRES_USER=raguser POSTGRES_PASSWORD=ragpass POSTGRES_DB=ragdb
  # optional: NEO4J_URI=bolt://localhost:7687 NEO4J_USER=neo4j NEO4J_PASSWORD=...
  adk web backend/aml/agents/stages --port 8001

Examples (select the matching agent in the picker):

  Run initial assessment for AML-SERVICES-SWIFT-2026-005
  Run transaction enrichment for AML-SERVICES-SWIFT-2026-005
  Run due diligence for AML-SERVICES-SWIFT-2026-005
  Run case analysis for AML-SERVICES-SWIFT-2026-005

The callbacks will:
  • resolve the case from `aml.cases`
  • enforce open gates (e.g. PARTIES_VERIFIED blocks due_diligence)
  • build the same prompt as each stage's `build_user_prompt`
  • bind `AgentToolContext` so write tools hit the real ledger
  • persist `agent_runs` + audit on completion (status AWAITING_REVIEW)
  • open stage gates (e.g. TE opens PARTIES_VERIFIED)
  • case_analysis: persist draft narrative via `finalize_adk_web_result`

Optional parity tools (full Orchestrator path, same as the frontend trigger):

  trigger_initial_assessment_via_orchestrator(case_number="...")
  trigger_transaction_enrichment_via_orchestrator(case_number="...")
  trigger_due_diligence_via_orchestrator(case_number="...")
  trigger_case_analysis_via_orchestrator(case_number="...")

Orchestrator mode (Sprint 4 — transport + A2A aware)
----------------------------------------------------
Set ``AML_ADK_MODE=orchestrator`` so hybrid callbacks delegate each turn to
``Orchestrator.trigger_agent`` instead of running the ADK LLM in-process.
This uses the same execution ports as production (``in_process`` or per-stage
``a2a`` from ``AML_AGENT_TRANSPORT_*``). No separate tool call required.

  export AML_ADK_MODE=orchestrator
  export POSTGRES_HOST=localhost POSTGRES_USER=raguser POSTGRES_PASSWORD=ragpass POSTGRES_DB=ragdb
  adk web backend/aml/agents/stages --port 8001

Example: ``Run due diligence for AML-SERVICES-SWIFT-2026-005``

Default ``AML_ADK_MODE=hybrid`` keeps the existing ADK-in-process + callback
persist path described above.

Production analyst UI still uses:
  POST /cases/{case_id}/agents/{agent}/trigger

Docker (optional)
-----------------
  docker run --rm -it -p 8000:8000 -v "$PWD:/app" -w /app \
    -e GOOGLE_API_KEY \
    aml/backend:dev adk web backend/aml/agents/stages --host 0.0.0.0 --port 8000

Deployable ADK server (REST + dev UI, Cloud Run)
------------------------------------------------
backend/aml/agents/fast_api_app.py serves the same stage agents via ADK's
get_fast_api_app (agents_dir = backend/aml/agents/stages). Run locally:

  uvicorn backend.aml.agents.fast_api_app:app --host 0.0.0.0 --port 8080
  curl http://localhost:8080/list-apps
    -> ["case_analysis","due_diligence","initial_assessment","rag_agent","transaction_enrichment"]

Container image: docker/Dockerfile.adk (Cloud Run target; honours $PORT).

agents-cli
----------
`agents-cli info` recognizes this repo ([tool.agents-cli] in pyproject.toml,
agent_directory = backend/aml/agents/stages).

NOTE: `agents-cli run "<prompt>"` (local mode) roots its api_server at the
project root and does not resolve our NESTED stage packages. Query the running
ADK server instead (works against uvicorn above or a deployed Cloud Run URL):

  agents-cli run "<prompt>" --url http://localhost:8080 --mode adk \
    --app-name due_diligence

Eval (per stage — see tests/eval/README.md)
-------------------------------------------
  adk eval backend/aml/agents/stages/<stage> \
    tests/eval/evalsets/<stage>.evalset.json \
    --config_file_path tests/eval/eval_config.json
